# 실험 02: 학습 데이터 시기만 다른 채점 모델 비교 (TiC-LM Oracle)

## 질문

실험 01에서 2023년 이후 데이터로 학습한 채점 모델(Llama-3.1/3.2, Gemma-3, SmolLM2)은 GPT-3.5/4 글의 entropy가 likelihood 상승을 상쇄해서 Fast-DetectGPT가 단순 Likelihood보다 낮아졌다. 증류, 크기, 정규화는 원인에서 빠졌고 학습 데이터 시기만 남았다. 다만 그 모델들은 데이터 시기 말고도 데이터 구성, 필터, 학습량, 구조가 모두 다르다.

이 실험은 **데이터 시기만 다르고 나머지는 같은 모델**로 같은 측정을 한다. ChatGPT 공개(2022-11-30) 전후로 상쇄가 달라지는지 본다.

## 모델

[TiC-LM](https://arxiv.org/abs/2504.02107) (Apple, ACL 2025)의 Oracle 시리즈 1B. 각 모델은 Common Crawl을 특정 달까지 모은 데이터로 처음부터 학습했다.

| 항목 | 내용 |
|---|---|
| 체크포인트 | 1B, 컷오프 2013-05, 2015-01, 2017-01, 2019-01, 2021-01, 2023-01, 2024-07 ([URL 목록](https://github.com/apple/ml-tic-lm/blob/main/models/model_checkpoints_urls.txt)) |
| 공통 | OpenLM 구조(1.4B 파라미터), GPT-NeoX 토크나이저, seq_len 2048, 같은 하이퍼파라미터, DCLM-Pool에서 같은 추출·필터(RefinedWeb 휴리스틱, 달 내부 중복 제거) |
| 다른 점 | 데이터 컷오프. 학습 토큰은 약 190B~224B이고, 2013-05만 약 112B(연속 학습 초기화용이라 절반) |
| 데이터 필터 | DCLM-Baseline의 마지막 fastText 품질 분류기는 쓰지 않았다. 그 분류기는 GPT-4가 만든 예시로 학습돼서, 논문이 인과성 문제로 뺐다. 그래서 "AI 글 같은 텍스트를 고르는 필터" 효과가 섞이지 않는다 |
| 이용 조건 | Apple ML Research Model TOU: 비상업적 연구 목적만 허용 |

컷오프 2023-01 모델은 ChatGPT 이후 약 2개월치 크롤만 포함하고, 2024-07 모델은 2023-01~2024-07 크롤(약 10개 덤프)을 포함한다.

## 미리 적어둔 예측 (결과를 보기 전, 2026-11-06)

**노출량이 작다.** 2024-07 모델 학습 데이터 중 2023년 이후 덤프는 전체 덤프 114개 중 약 10개라 토큰으로 대략 10~15%다. 웹 페이지 중 AI 글 비율은 2023~2024년 평균 몇 % 수준으로 보고된다([uneven rise](https://arxiv.org/abs/2610.36631)). 둘을 곱하면 학습 데이터 중 AI 글은 1% 미만으로 추정된다. Llama 같은 모델이 본 양은 공개되지 않았지만, 품질 필터와 합성 데이터 때문에 이보다 클 가능성이 높다.

이를 고려한 판정 기준:

| 결과 | 해석 |
|---|---|
| 2023-01 → 2024-07에서 keep 비율이 뚜렷이 떨어지고(쌍 bootstrap 95% CI가 0 아래), 2015~2023 사이에는 일관된 추세가 없음 | 1% 미만의 노출로도 상쇄가 생긴다. 데이터 쪽 설명에 대한 강한 증거 |
| 2015~2024 내내 비슷한 속도로 떨어짐 | AI 글이 아니라 웹 텍스트 자체의 시간 변화(문체, 템플릿 증가 등)일 수 있음. AI 노출 설명이 약해짐 |
| 변화 없음 | 노출량이 너무 작아서일 수도, 원인이 웹 AI 글이 아니라 큐레이션·합성 데이터 쪽일 수도 있음. 이 실험만으로는 구분 불가 → 노출량을 직접 조절하는 실험(아래 다음 단계)이 필요 |

실험 01의 비교 기준: GPT-Neo-1.3B(2020 Pile) keep 64%, OLMo-2 1B 75%, SmolLM2 39%, Llama-3.2-1B 33% (GPT-3.5/4 6세트 평균).

## 구현

- [openlm.py](openlm.py): OpenLM 원본 라이브러리는 import 시점에 xformers가 필요해서 Windows 환경에서 그대로 못 쓴다. 추론에 필요한 부분만 순수 PyTorch로 다시 구현했다. 체크포인트는 `torch.load(weights_only=True)`로 읽는다.
- [check_openlm.py](check_openlm.py): (1) 원본 open_lm 코드(9bb92ef)와 같은 가중치로 logits 비교(선택, `--open_lm_src`가 있을 때만), (2) rotary 표 계산 정밀도를 위치별 loss로 결정, (3) GPU fp16과 CPU fp32의 점수 차이 확인.
- [analyze_token_shift.py](analyze_token_shift.py): 두 컷오프 모델의 같은 토큰에서 entropy·surprisal 변화를 비교하고, 감소량이 큰 토큰 종류를 뽑는다.
- [score_oracles.py](score_oracles.py): 실험 01과 같은 9개 세트, 같은 점수 함수(`scores_from_logits`). 토큰별 L/E를 항상 저장한다.
- [analyze.py](analyze.py): 컷오프별 AUROC, keep 비율, 토큰 통계, 인접 컷오프 간 keep 차이의 쌍 bootstrap.

```bash
# 체크포인트 (1B 7개, 각 5.8GB) -> data/tic-lm/oracles_1b_220b/<YYYYMM>/{params.txt,checkpoints/epoch_*.pt}
B=https://ml-site.cdn-apple.com/models/tic-lm/oracles_1b_220b
for m in 202407 202301 202101 201901 201701 201501 201305; do e=21; [ $m = 201305 ] && e=12
  d=data/tic-lm/oracles_1b_220b/$m; mkdir -p $d/checkpoints
  curl -sf -o $d/params.txt $B/$m/params.txt; curl -sf -C - -o $d/checkpoints/epoch_$e.pt $B/$m/checkpoints/epoch_$e.pt; done

python experiments/02_tic_lm_data_era/check_openlm.py --ckpt_dir data/tic-lm/oracles_1b_220b/202407
python experiments/02_tic_lm_data_era/score_oracles.py --months 202407 202301 202101 201901 201701 201501 201305
python experiments/02_tic_lm_data_era/analyze.py
python experiments/02_tic_lm_data_era/analyze_token_shift.py --a 202301 --b 202407
python experiments/02_tic_lm_data_era/analyze_token_shift.py --a 202101 --b 202301   # 대조 구간
```

## 결과 (2026-11-06)

### 0. 구현 확인

- 원본 open_lm 코드와의 logits 대조(check 1)는 하지 않았다. 클론한 외부 저장소 코드를 실행하는 단계라 이 환경의 자동 권한 검사에서 막혔다. 구조는 원본 코드를 읽고 맞췄고, 아래 두 가지로 간접 확인했다.
  - 사람이 쓴 XSum 글 4개의 평균 NLL 2.55 nat/token. 1B 모델로 정상 범위다.
  - 2048토큰 글에서 위치별 loss가 위치가 뒤로 가도 무너지지 않는다(아래 rotary 표 참고). 구조가 틀렸다면 바로 드러나는 부분이다.
- rotary 표: 체크포인트의 `inv_freq`는 bf16으로 반올림된 값으로 저장돼 있다(0.866 → 0.8672). 세 가지를 비교했다.
  - 정확한 fp32
  - 주파수만 bf16(`inv_bf16`)
  - 위치와 곱까지 bf16
  - 앞의 두 가지는 위치별 loss 차이가 0.0001 nat 이하다. 위치까지 bf16으로 만들면 1024~2048 위치에서 +0.31 nat 나빠진다. 학습은 위치를 정확하게 계산한 것이다. fp32를 쓴다.
- GPU fp16과 CPU fp32의 차이(10개 글): FDG 최대 0.006, 토큰 평균 log-likelihood 최대 0.0003.

### 1. 컷오프별 탐지 성능

GPT-3.5/4 6세트 평균(chat)과 davinci 3세트 평균(dav)이다. keep은 AI−사람 likelihood 차이 중 entropy에 상쇄되지 않고 남은 몫이다.

| 컷오프 | FDG chat | Lik chat | FDG<Lik (/6) | keep chat | ΔL chat | ΔH chat | xsum_gpt-4 FDG (keep) | FDG dav | Lik dav |
|---|---|---|---|---|---|---|---|---|---|
| 2013-05 (학습량 절반) | 0.937 | 0.914 | 2 | 68% | 0.639 | −0.226 | 0.923 (90%) | 0.847 | 0.762 |
| 2015-01 | 0.941 | 0.914 | 2 | 69% | 0.634 | −0.219 | 0.929 (95%) | 0.850 | 0.763 |
| 2017-01 | 0.938 | 0.911 | 2 | 69% | 0.626 | −0.218 | 0.914 (92%) | 0.854 | 0.765 |
| 2019-01 | 0.937 | 0.910 | 2 | 69% | 0.627 | −0.220 | 0.908 (96%) | 0.862 | 0.763 |
| 2021-01 | 0.940 | 0.915 | 2 | 68% | 0.633 | −0.229 | 0.918 (92%) | 0.864 | 0.765 |
| 2023-01 | 0.943 | 0.918 | 2 | 67% | 0.640 | −0.237 | 0.924 (90%) | 0.866 | 0.766 |
| **2024-07** | **0.892** | **0.949** | **6** | **38%** | **0.770** | **−0.479** | **0.789 (35%)** | 0.869 | 0.767 |
| 참고: GPT-Neo-1.3B | 0.928 | 0.882 | 0 | 64% | | −0.219 | 0.888 (72%) | | |
| 참고: Llama-3.2-1B | 0.800 | 0.904 | 6 | 33% | | −0.430 | 0.594 (14%) | | |

인접 컷오프 사이 keep 변화(텍스트 쌍을 다시 뽑는 쌍 bootstrap 2000회, 95% CI):

| 구간 | 변화 | 95% CI |
|---|---|---|
| 2013-05 → 2015-01 | +1.2%p | [+0.5, +2.0] |
| 2015-01 → 2017-01 | −0.5%p | [−1.2, +0.3] |
| 2017-01 → 2019-01 | +0.4%p | [−0.4, +1.1] |
| 2019-01 → 2021-01 | −1.6%p | [−2.5, −0.9] |
| 2021-01 → 2023-01 | −1.0%p | [−1.8, −0.2] |
| **2023-01 → 2024-07** | **−28.7%p** | **[−30.8, −26.9]** |

- ChatGPT 이전 컷오프 6개는 keep 67~69%로 거의 같고, GPT-Neo·OLMo처럼 FDG가 Likelihood보다 높다.
- 2024-07 하나만 SmolLM2·Llama 수준으로 무너진다. 6세트 모두 FDG < Likelihood가 된다.
- 2024-07에서 AI−사람 likelihood 차이도 0.640 → 0.770으로 커진다. 그래서 Likelihood 탐지는 오히려 좋아진다. 하지만 entropy 차이가 −0.237 → −0.479로 두 배가 돼서 그 이상을 상쇄한다. RoFT가 보고한 "노출되면 likelihood 탐지가 좋아진다"와 우리가 본 "정규화 점수는 망가진다"가 같은 모델에서 동시에 나타난다.
- davinci 글(ChatGPT 이전 GPT-3)의 점수는 2023-01과 2024-07이 거의 같다(FDG 0.866 → 0.869). 변화는 채팅 모델이 쓴 글에만 생긴다.
- 컷오프마다 학습은 한 번씩만 했으므로 seed 변동을 직접 잴 수는 없다. 다만 독립적으로 학습한 ChatGPT 이전 모델 6개가 서로 ±1.6%p 안에 있다. 이게 학습 무작위성과 시기 변화를 합친 변동 폭의 경험적 기준이 된다.

### 2. 토큰 단위: 무엇이 바뀌었나

같은 토큰에서 두 모델의 entropy E와 surprisal L을 비교했다([analyze_token_shift.py](analyze_token_shift.py)). GPT-3.5/4 6세트의 이어 쓴 부분 토큰만 썼고, AI 글은 129,252토큰, 사람 글은 125,997토큰이다.

| 구간 | AI 평균 ΔE | AI 평균 ΔL | AI 토큰 중 ΔE < −0.5 | 사람 평균 ΔE | 사람 토큰 중 ΔE < −0.5 |
|---|---|---|---|---|---|
| 2021-01 → 2023-01 (대조) | −0.015 | −0.012 | 6.6% | −0.004 | 8.2% |
| 2023-01 → 2024-07 | **−0.340** | **−0.174** | **31.2%** | +0.003 | 7.9% |

- entropy 감소는 특정 표현이 아니라 AI 글 전체에 퍼져 있다.
  - 감소량이 가장 큰 토큰은 ` the`, `,`, ` a`, ` and`, `.`, 줄바꿈, ` to`, ` of` 같은 기능어다. 상위 20개 토큰 종류가 전체 감소량의 30%만 차지한다.
  - 대조 구간에서는 AI 글에서도 거의 변화가 없다.
- 사람 글은 두 구간 모두 변화가 없다.
- 해석: 2024-07 모델은 맥락이 채팅 모델 문체이면 다음 토큰 전체를 더 확신 있게 예측한다. 특정 단어를 외운 게 아니라 채팅 모델 문체를 하나의 익숙한 분포로 배운 것으로 보인다.
- L–E coupling β는 모든 컷오프에서 AI 0.88~0.90, 사람 0.96~0.99로 거의 같다. 실험 01과 같이, β는 이 현상을 구분하지 못한다.
- xsum_gpt-4에서 저entropy 20% 토큰의 (L−E)는 AI 쪽이 −0.064 → −0.002로 사람(−0.010) 쪽에 거의 붙는다. Llama에서 본 역전의 초기 형태다.

### 3. 판정

미리 적어둔 기준의 첫 번째 경우다. ChatGPT 이전 구간에는 일관된 추세가 없고, 2023-01 → 2024-07에서만 CI가 0에서 멀리 떨어진 큰 하락이 있다. 그 원인으로 추정한 노출량은 학습 데이터의 1% 미만이다.

실험 01에서 남은 설명이던 "2023년 이후 학습 데이터"가 다른 조건을 모두 고정한 상태에서 재현됐다. 아직 남은 질문은 다음과 같다.

- **2023~2024 웹의 무엇 때문인가.** AI가 생성한 글 때문인지, 같은 시기 웹의 다른 변화(SEO·마케팅 글 증가, 사람이 ChatGPT 문체를 닮아가는 것) 때문인지는 이 실험으로 구분되지 않는다. davinci·사람 글은 변하지 않고 채팅 모델 글에서만 변한다는 점은 AI 글 쪽을 가리키지만, 직접 증거는 아니다.
- **노출량.** 2024-07 모델의 학습 데이터 중 AI 글 비율을 직접 재지 않았다. 덤프 수와 웹 AI 비율 추정치로 계산한 1% 미만은 추정이다.
- **크기.** 1B에서만 확인했다. 3B Oracle도 공개돼 있다.
- **일반화.** 평가 글은 2023년 GPT-3.5/4 글이다. 2024-07 모델이 웹에서 본 것과 같은 모델의 글이다. 2024-07 이후 공개된 채팅 모델의 글에도 같은 현상이 생기는지 봐야 "채팅 문체 일반"이라고 말할 수 있다.
